## Our project proposal

*About one page. Graded with the starting plan at 40%.*

*Help the reader picture someone using it: what can they do, what choices do
they make, what happens as a result. Name the features that make it worth
building and explain how they fit together. "An educational app with lots of
features" leaves your grader guessing.*

*Three constraints from the handouts:*

- *It must be **one application whose parts work together**. A casino where each
  person builds a separate game behind a menu is explicitly rejected, because it
  requires almost no coordination.*
- *Target scope is comparable to **A1 and A2 combined**, and it does **not** grow
  with team size. Meeting that is full scope credit.*
- *It must be a **new** OCaml project, not a continuation of a course assignment
  and not work submitted for another course. Substantial behavior in OCaml; a
  thin wrapper around a library that already does the job does not count.*

**Our backup idea.** *One paragraph. Choose something that gives a plausible way
forward if the main idea collapses, usually because a library will not do what
you need. If both ideas depend on the same uncertain library, the backup does
not help. Switching ideas does not extend any deadline.*
